## Known limits

- **L01**: The emulator's Android Keystore is software-backed, so the key protection of the stored tokens is not hardware-backed there.
- **L02**: Re-consent for new user data (Health Card's phone number) asks for the ID and OTP again: eSignet's identity system releases user data only after an authentication, and eSignet Go keeps no browser session; Health Card's explainer screen says so. Extra scopes that need no new user data (the permission health_card_share) are approved on eSignet's consent page with no login (rule R28). The consent page shows a plain-language description of the permission from the setting oauth.native_sso.consent_scope_descriptions.
- **L03**: The default stack keeps eSignet's runtime store in memory, so an eSignet restart ends every Hub session (the e2e suite uses this to test the ended session) and two replicas would not share sessions, consent tickets or DPoP jti entries. eSignet's Redis store works with the compose profile redis (PS03_RUNTIME_STORE=redis, row E2E-REDIS); a deployment with several replicas must use it. Several replicas behind a load balancer were not run.
- **L04**: Sign-out ends the login session on the server (rule R27). Health Card's access tokens carry that session id, so userinfo, introspection and the OpenID4VCI endpoint refuse them afterwards (e2e TestE2E_Revoke_DeviceSecret). Not covered: a resource server that checks a token's signature without asking eSignet accepts it until it expires, and Hub's own access token from its login (no session id) lives until it expires; Hub deletes it at sign-out. Without network the session record ends by its time to live; the deleted DPoP key already blocks every exchange.
- **L05**: Hosted CI runs only on pushed commits: the last hosted run (38565036088, 2026-10-14, every job passed) is at b73ac56, and the commits after it were checked locally (the rows above) until they are pushed. The repository is public, so anyone can open the run page. Every job was also replayed on Linux containers here (row CI-LINUX).
- **L06**: Emulator tests run on one emulator image (AVD ps03_api34, Google APIs x86_64, API 34, Chrome 113), not on other Android versions or browsers. The browser login steps of the UI tests can time out on a busy machine; a rerun passes. On 2026-10-14 eSignet's send-otp call to the mock identity system sometimes failed after 10 s during the browser login, while direct calls to the same endpoint (from a container on the stack network and from the eSignet container) answered in under a second; the cause is not known. The headless e2e logins were not affected.
- **L07**: The upstream Postman folders need the Postman desktop app (they use WebCrypto and top-level await that newman 6.2.2 lacks); nobody on the team has run them there. The Native SSO folder runs under newman.
- **L08**: A TalkBack pass by a person was done on 2026-10-24 on a OnePlus CPH2569 (item M02, PASS); the tester reported no issues and no per-item notes were recorded. Automated checks still cover labels, touch targets, reading order and contrast: an accessibility scan with Google's Accessibility Test Framework on every app screen of the emulator UI tests (row UI-A11Y; it cannot read the text colour of Compose text, so contrast comes from HubThemeTest and CardThemeTest), and JVM screen tests of both apps at 200 % font (HubScreensTest, CardScreensTest).
- **L09**: One physical phone was used (OnePlus CPH2569, Android 15, 2026-10-24, item M03, PASS); other phones and Android versions were not tried. The phone has no StrongBox, so the keys ran in the TEE (Hub logged `DPoP key: TEE_OR_SOFTWARE`). Nothing was run on Linux or macOS machines of the team; the Go tests run in a Linux container on a Windows 11 laptop, and the CI jobs were replayed in Linux containers there.
- **L10**: Health Card signs in silently for as long as Hub's device secret and its login session live (native_sso.device_secret_validity_seconds, 8 h by default; no id_token age cap by default, D8). After that the exchange is refused (invalid_request for an expired device secret) and Health Card shows "eSignet did not accept the sign-in (code invalid_request)". Hub cannot read the device secret, so its home screen counts 8 h from the sign-in: "Yes, until <time>", then "Ended at <time>. Sign out and sign in again to share it." (HubScreensTest); the count assumes the server default lifetime. An operator who sets oauth.native_sso.id_token_max_age_seconds (hardening) gets the same dead end after that many seconds, with invalid_grant.
